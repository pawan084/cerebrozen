BUG-01  [CRASH]  Notification inbox "Open" navigates to a route that doesn't exist
--------------------------------------------------------------------------------
Files:
  notify/NotificationLog.kt:128        routeFor("checkin") -> "today"
  notify/Reminders.kt:104              records the daily nudge with route "today"
  notify/Push.kt:152                   same map for server nudges
  ui/screens/NotificationInbox.kt:134  onOpen(route)
  ui/CereBroApp.kt:657                 navController.navigate(route)  <- no guard

Problem:
  There is NO composable("today") in the graph. The Home tab route is "home"
  (Tab.Home at CereBroApp.kt:188). navigate("today") throws
  IllegalArgumentException: "Navigation destination that matches route today
  cannot be found" -> app crashes.

Repro:
  Settings > Reminders > turn daily reminder on > let it fire (or trigger
  ReminderReceiver) > open Notifications inbox > tap "Open" on the check-in row.

Extra:
  app/src/test/java/com/cerebrozen/app/notify/NotificationLogTest.kt:96
  asserts assertEquals("today", routeFor("checkin")) — the test PINS the bug,
  so it must be updated together with the fix.

Fix:
  NotificationLog.kt:128 -> "home"
  Also add a guard in CereBroApp.kt open(): ignore a route not in the graph
  instead of crashing.

BUG-02  [HIGH]  Daily plan screen: eternal "Loading your plan…" when no plan exists
--------------------------------------------------------------------------------
File: ui/screens/TodayScreen.kt:2747-2751, 2802  (ReferenceDailyPlanScreen)

Problem:
  Api.activePlan() is `runCatching{...}.getOrNull()` (net/Session.kt:853) — it
  NEVER throws. So `.onFailure { error = ... }` can never fire. No plan (or a
  network failure) returns null, plan stays null, and the branch
  `plan == null -> Text("Loading your plan…")` renders forever. No empty state,
  no retry.

Note:
  The real PlanScreen.kt:72 has an explicit comment "retry instead of an eternal
  'Loading…'" and a `loadError` flag. The Reference copy reintroduced the exact
  bug that was already fixed once.

Fix:
  Add a `loaded` boolean set after the LaunchedEffect, and branch:
  !loaded -> loading; loaded && plan == null -> empty state + retry.

--------------------------------------------------------------------------------
BUG-03  [HIGH]  "Begin next unfinished step" marks the step DONE instead of opening it
--------------------------------------------------------------------------------
File: ui/screens/TodayScreen.kt:2816-2821  (ReferenceDailyPlanScreen)

Problem:
  The CTA finds the first not-done step and calls toggle(next), which is
  Api.togglePlanStep(id, done = true). The button says "Begin" but it ticks the
  step off without the user doing anything.

Fix:
  Route to the step's surface (planStepRoute(symbol), TodayScreen.kt:225) and
  leave completion to the row's own tap.

BUG-04  [HIGH]  Reminders screen saves nothing — and the inbox reads what it never wrote
--------------------------------------------------------------------------------
File: ui/screens/TodayScreen.kt:2573-2639  (ReferenceRemindersScreen, route "reminders")

Problem:
  a) All 5 toggles are local `remember` state.
  b) Times are hardcoded strings: "20:30", "21:15", "19:00", "13:00",
     "10:00 PM–7:00 AM".
  c) "Save reminder schedule" (line 2636) has an EMPTY body: `{ }`.
  d) It never writes prefs "reminder_on" / "reminder_hour", never calls
     Reminders.schedule(), never requests POST_NOTIFICATIONS.

  Consequence: NotificationInbox.kt:55-56 READS reminder_on/reminder_hour.
  User toggles reminders on -> inbox still says "no reminder scheduled" ->
  and no notification ever fires.

  The real working screen — RemindersScreen (ui/screens/Settings.kt:556) with
  permission flow, TimePickerDialog, Reminders.schedule(), on-resume
  revoked-permission banner — is IMPORTED at CereBroApp.kt:140 but NEVER ROUTED.
  6 places in the app link to "reminders".

Fix:
  CereBroApp.kt:781 -> composable("reminders") { RemindersScreen(onBack = back) }
  (or port the Dawn visual onto the real screen's logic).

BUG-05  [HIGH]  Baseline saves to a prefs key nothing reads
--------------------------------------------------------------------------------
Files:
  ui/screens/TodayScreen.kt:3032, 3072  (ReferenceBaselineScreen, route "baseline")
  ui/screens/Baseline.kt:64             (BaselineScreen — orphaned)
  ui/screens/Extras.kt:629              (InsightsScreen reads BaselineStore)

Problem:
  The routed screen writes 4 sliders (1-10) into SharedPreferences
  "personal_baseline". Grep shows nothing else in the app reads that key.
  Insights' "Your starting point" card reads BaselineStore (Stores.kt:38),
  which is only written by the ORPHANED BaselineScreen (imported at
  CereBroApp.kt:71, never routed).
  Result: the baseline card on Insights can never populate. 3 links point at
  the broken screen.

Also a scale mismatch: Reference uses 1-10 with 4 dimensions
(stress/sleep/mood/energy); BaselineStore + Insights use 1-5 with 2
(stress/sleep).

Fix:
  Route "baseline" to BaselineScreen, or make ReferenceBaselineScreen write
  BaselineStore.set() on the 1-5 scale.

--------------------------------------------------------------------------------
BUG-06  [MEDIUM]  Sleep insights passes a day-count into a row-limit parameter
--------------------------------------------------------------------------------
File: ui/screens/TodayScreen.kt:2461-2465  (ReferenceSleepInsightsScreen)

Problem:
  `Api.sleepLogs(days)` — but the signature is sleepLogs(limit: Int?) and it
  builds "/sleep?limit=N" (net/Session.kt:664). limit = number of ROWS, not days.
  Selecting "Week" fetches the 7 most recent logs regardless of their dates —
  if the user logged 7 nights spread over 2 months, "Week" shows 2 months.
  Api.sleepSummary(days) on the next line IS day-based, so the stat tiles and
  the bar chart describe different windows.

Fix:
  Either add a days parameter to /sleep on the client, or filter client-side
  by date before charting.

--------------------------------------------------------------------------------
BUG-07  [MEDIUM]  Goals screen hides resolved goals with no way to see them
--------------------------------------------------------------------------------
File: ui/screens/TodayScreen.kt:2842  (ReferenceGoalsScreen)

Problem:
  Calls Api.goals() with the default includeResolved = false. The API doc at
  net/Session.kt:768-773 explicitly says the client-only-asks-for-active bug was
  already fixed once because "Done"/"Let it go" made a user-authored goal vanish
  with no way back. The Reference screen brought it back — and it has no
  Done/Let-go buttons at all, so a goal can only be created, never resolved.

Fix:
  Route "goals" to the real GoalsScreen (imported CereBroApp.kt:132, never
  routed) which has status changes AND habits.

--------------------------------------------------------------------------------
BUG-08  [MEDIUM]  Breathing prep screen's three settings do nothing
--------------------------------------------------------------------------------
File: ui/screens/PracticeLibraryScreen.kt:142-195  (PracticeBreathingScreen,
      route "breathing-intro")

Problem:
  "Soft chime", "Haptics", "Keep screen awake" are local `remember` booleans.
  They never write Chime.breatheChimeEnabled (audio/Chime.kt:43), never persist,
  and keep-awake is never applied to the window. The real chime toggle lives
  inside the session at Breathe.kt:474 — so the prep screen and the session
  disagree.

Fix:
  Wire the toggles to Chime.breatheChimeEnabled / a prefs-backed store, or drop
  them from the prep screen.

--------------------------------------------------------------------------------
BUG-09  [MEDIUM]  Guest mode shows network errors instead of a guest state
--------------------------------------------------------------------------------
Files: net/Session.kt:50, 522-531; ui/CereBroApp.kt:517

Problem:
  Session.guestMode only gates the auth screen. Inside the app every Api.* call
  hits ensureAccess(), which for a guest throws ApiException(401, "Signed out").
  Server-backed screens then render their failure copy, e.g.
  "Couldn't load patterns. Please try again." / "Couldn't load goals."
  A guest who never signed in is told the network failed.
  Session.kt:48 promises guest mode "only opens the offline-capable product
  shell" — no screen implements that distinction.

Fix:
  Branch on Session.guestMode before the fetch and render a "sign in to save
  this" state instead of an error.
