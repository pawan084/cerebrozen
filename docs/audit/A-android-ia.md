# Android IA audit — tab order, feature sequence, placement, reachability (2026-08-04)

Scope: `apps/android/app/src/main/java/com/cerebrozen/app/` — navigation graph in `ui/CereBroApp.kt` (5 tabs, ~45 routes), every tab page, every hub, onboarding, notifications. Tags: SEQ = ordering, PLACE = placement/discoverability, BUG = broken/orphaned/conflicting paths, POLISH = small but real.

1. [BUG] FCM nudges set a `deeplink` URI on the launch intent but MainActivity never reads intent data and the NavHost registers no deep links — a server nudge promising "your wind-down" always dumps the user on Home, breaking the one promise a notification makes (Push.kt:122-124; MainActivity.kt:17-31; CereBroApp.kt:522-623).
2. [BUG] Re-enabling reminders from Settings calls `Reminders.schedule(context)` with the default hour 9, discarding the onboarding "evening" (19:00) choice — a user who toggles the switch off/on gets a silent 9 am reminder they never asked for (Settings.kt:446,455; Reminders.kt:46; OnboardingScreen.kt:240-245).
3. [BUG] BootReceiver also re-arms at the default hour 9 — every reboot silently moves an evening user's reminder to the morning while the toggle still reads "on" (Reminders.kt:90-98).
4. [PLACE] The Reminders screen offers only on/off with no time control — morning/evening exists solely as an onboarding chip and can never be revisited or corrected afterwards (Settings.kt:438-478; OnboardingScreen.kt:228-232).
5. [BUG] The whole offline CBT-I program route `cbti` is registered but has zero inbound links — a complete module course with per-module progress persistence shipped unreachable (CereBroApp.kt:593; OfflineProgramsScreen.kt:37).
6. [BUG] The offline MBCT program route `mbct` is likewise orphaned — same shipped-but-unreachable course (CereBroApp.kt:594; OfflineProgramsScreen.kt:40).
7. [BUG] `bodyscan` is registered with no opener anywhere, even though Sleep's wind-down ritual embeds a body-scan step — the standalone practice can never be run on its own (CereBroApp.kt:590; OfflineGuidanceScreens.kt:180).
8. [BUG] `crisisgrounding` — a crisis-specific grounding screen with a built-in handoff to box breathing — is orphaned, which is precisely the calming affordance the Crisis screen lacks (CereBroApp.kt:591; OfflineGuidanceScreens.kt:229).
9. [BUG] `insightreel` is registered with zero inbound links — another finished surface no user can reach (CereBroApp.kt:592; OfflineGuidanceScreens.kt:287).
10. [BUG] Two guided-imagery implementations coexist: the Toolkit's `imagery` (Rituals.kt:760) and the orphaned offline `guidedimagery` (OfflineGuidanceScreens.kt:118) — a duplicate of the same behavior, one of them dead (CereBroApp.kt:589,599).
11. [BUG] `onegoodthing` and `intention` routes plus their full screens are still registered and maintained with no inbound path — the Oracle maps `one_good_thing`/`intention_set` to `journal` instead, so the screens are dead weight that will silently drift (CereBroApp.kt:610-611; ToolScreens.kt:198-225; TalkScreen.kt:156).
12. [POLISH] `talk/live` and `talk/chat` aliases have no remaining callers and, because `shouldShowBottomBar` excludes them, would render Talk without the tab pill — a legacy entry shows a chrome-less Talk (CereBroApp.kt:546-547,150-151).
13. [PLACE] The journal-saving breathing practice (route `breathing`) is reachable only when the Oracle happens to attach a breathing widget — it appears in no menu, so most users can never discover it (CereBroApp.kt:607; TalkScreen.kt:149; ToolScreens.kt:57).
14. [BUG] Two breathing engines exist: `breathe/box` runs BreathLoopsScreen's own pacing/orb/ViewModel while reset, onboarding, wind-down and the practice all share `BreatheEngine` — rhythm and visuals can drift between the app's two most-linked breathing doors, against the one-engine rule (BreathLoopsScreen.kt:108; Breathe.kt:198,445; Rituals.kt:328; ToolScreens.kt:67).
15. [POLISH] Counting the games hub's breathing-rhythm, four breathing surfaces are reachable (`breathe/box`, `breathe/reset`, `breathing`, `mindfulgame/breathing-rhythm`) — over the one-implementation-per-behavior cap, so users meet three different breathing UIs for one skill (MindfulGameRegistry.kt:89).
16. [BUG] The Journal elevated-risk support card names Tele-MANAS 14416 only as plain body text — no dial affordance, no route to Crisis — so risk is surfaced without a tappable pathway, unlike Talk's crisis card which dials and links (JournalScreen.kt:635-643; res/values/strings.xml:507; contrast TalkScreen.kt:907-928).
17. [SEQ] That support card renders at the bottom of the Journal hub, below the hero, two write buttons, two nav rows and the recent entries — after saving a heavy entry it is likely below the fold at the exact moment it exists for (JournalScreen.kt:634-643).
18. [PLACE] CrisisScreen never links the user's own safety plan — the document written for this exact moment is reachable only via You → Safety plan, a calm-state path a person in crisis won't retrace (Extras.kt:2537-2594; Screens.kt:251-252).
19. [PLACE] CrisisScreen offers phone lines and a trusted-contact door only, no grounding or breathing route — users who cannot make a call dead-end on a list of numbers while the purpose-built CrisisGroundingScreen sits orphaned (Extras.kt:2558-2593).
20. [BUG] The crisis directory is a hardcoded India list (Tele-MANAS/112/Kiran) rendered regardless of the You → Crisis region setting — a user who set US/GB still sees Indian numbers with only findahelpline as an escape, so the region setting visibly does nothing on the surface it names (Extras.kt:2552-2557 vs Settings.kt:219-244).
21. [BUG] The quick-dial pills on You's Support card and Talk's crisis card hardcode `tel:14416` — after choosing a non-IN region the one-tap path still dials an India-only number (Screens.kt:166-173; TalkScreen.kt:912-919).
22. [SEQ] The Toolkit's "Support, any time" card is the last of ~14 cards — a user routed here from Talk's SOS ("when talking feels like too much") must scroll the entire practice catalogue before urgent support appears (Extras.kt:2045-2049).
23. [PLACE] Talk's SOS door promises "Quick SOS reset — 2 minutes" but opens the whole Toolkit hub, not the two-minute reset that exists at `breathe/reset` — a distressed user lands on a menu instead of the exercise the label named (TalkScreen.kt:1235-1238; res/values/strings.xml:158-159).
24. [BUG] A server "breathing" suggestion routes to `breathe/box` when it arrives as a chip but to `breathing` when it arrives as an Oracle widget — the same suggestion opens two different surfaces depending on transport (TalkScreen.kt:1220 vs 149).
25. [PLACE] The Toolkit behaves like a sixth top-level area — it is the target of Home's door, Talk's SOS chip and offline banner, plan steps, and ritual outros — yet lives one push deep behind a back arrow; the entire practice library is never one tap away while five tabs are (Extras.kt:1931; TodayScreen.kt:1259; TalkScreen.kt:801,1235; Rituals.kt:884).
26. [BUG] Cross-tab links use `open()` (plain `navigate` + launchSingleTop) instead of the tab pill's popUpTo/saveState pattern — Home's avatar→You, banners→Sleep and Talk's mood_check widget→Home push duplicate tab entries so back walks Home→Talk→Home instead of tab history (CereBroApp.kt:535-537 vs 513-517; TodayScreen.kt:859,894; TalkScreen.kt:153).
27. [PLACE] NowPlayingBar renders only on Sleep and Sounds — audio started from Home's rail keeps playing on Home/Talk/Journal/Toolkit with no visible transport, so pausing means going hunting for the Sleep tab (SleepScreen.kt:633; Extras.kt:961).
28. [BUG] Tapping the currently-playing item on Home's rail always restarts it (`Player.play`) while the identical row on Sleep toggles pause — two paths to one track behave oppositely mid-listen (TodayScreen.kt:534-537 vs SleepScreen.kt:820-827).
29. [BUG] Favourite hearts exist on Sounds-hub rows but not on the identical served rows in the Sleep tab list — the same sleep story is favouritable on one path and not the other, so the favourites feature looks flaky (Extras.kt:1000-1004 vs SleepScreen.kt:815-830).
30. [SEQ] The "Say more in Journal" bridge disappears 8 s after a check-in when the confirmation settles into one line — the journaling invitation expires before a slow reader acts and never returns for that check-in (TodayScreen.kt:991-997,1058-1105).

33. [PLACE] `planStepRoute` maps "wind*" steps to `toolkit` — the plan hero's START chip for an evening wind-down step drops the user at the top of a 14-card hub instead of the `winddown` ritual or `sounds/mixer` that exist for it (TodayScreen.kt:192-198,1211).
