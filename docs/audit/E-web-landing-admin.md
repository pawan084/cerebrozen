## Landing site (apps/web)

1. [CLAIM] Twilio is a live subprocessor but is missing from /subprocessors — the page asserts "nothing here that isn't wired in backend/app/services", yet `backend/app/services/sms.py` wires Twilio for trusted-contact SMS escalation; SMTP email relay is likewise unnamed. Privacy policy §4 also omits both (apps/web/app/subprocessors/page.tsx:13; backend/app/services/sms.py:1; apps/web/app/privacy/page.tsx:77).
2. [CLAIM] "Premium + Human ₹1,499/month" is priced on the landing while PRD calls it the "sharpest honesty risk in the product": `premium_human` is sellable but buys only an unlimited chat quota — no provider, no booking, no handoff. "(rolling out)" understates "does not exist", and no CLAIMS_MAP row covers the tier (apps/web/app/page.tsx:51; docs/PRD.md:112).
3. [CLAIM] Premium item "Richer voice sessions" has no mechanism — voice is not metered or tier-gated anywhere (`services/usage.py` meters chat only; CLAIMS_MAP §4 banned "unlimited voice" for exactly this class of implied meter). No CLAIMS_MAP row (apps/web/app/page.tsx:48; backend/app/services/usage.py:22).
4. [CLAIM] "Agentic plans" listed as a Premium-only feature, but the agentic daily plan ships to every tier (PRD §2 marks it ✅ with no tier gate; only chat messages are quota'd) — the pricing table implies a gate that does not exist (apps/web/app/page.tsx:48; docs/PRD.md:59).
5. [CLAIM] Journal space card promises "lock it behind Face ID if you like", but its CTA opens the browser app (`appHref("/journal")`) where no biometric lock exists — Face ID is an iOS feature and the iOS app is not downloadable. The claim is true only for a client the visitor cannot reach from that button (apps/web/app/page.tsx:28,289).
6. [CLAIM] FAQ "Does it work offline?" answers in present tense about "the mobile apps" ("core tools … work without a connection") when neither mobile app is installable by the public — the same FAQ admits iOS "has no public date yet" two answers earlier (apps/web/app/page.tsx:67).
7. [CLAIM] Proactive pill "Timed check-ins when patterns shift" — pattern-mined nudging is explicitly deferred work ("patterns into nudges/plan changes" in the PRD's future list); the shipped scheduler is contextual/bedtime-derived, not pattern-shift-triggered. No CLAIMS_MAP row (apps/web/app/page.tsx:35; docs/PRD.md:266).
8. [CLAIM] Bento cell "the ring … never resets, and nothing ever counts your misses" is a doubtable behavioral guarantee with no CLAIMS_MAP row/test, and describes the mobile presence ring while the page's doors all lead to the browser app (apps/web/app/page.tsx:244; docs/CLAIMS_MAP.md).
9. [CLAIM] Terms §6 says paid plans "are managed through your app-store account" — no store app exists and web billing isn't live; /refunds states this honestly, so the two trust pages contradict each other (apps/web/app/terms/page.tsx §6 vs apps/web/app/refunds/page.tsx).
10. [CLAIM] Footer link is labeled "Crisis support" but /support contains zero crisis numbers — no Tele-MANAS 14416, no hotline list, only "contact your local emergency services". The landing itself claims region-correct lines "always a tap away"; on the website, the crisis-labeled page has nothing tappable (apps/web/components/SiteFooter.tsx:59; apps/web/app/support/page.tsx:54-61).
11. [CLAIM] "Launch pricing · India, shown in ₹. Cancel anytime." — nothing is purchasable on any surface (no web billing, no store apps), so "cancel anytime" describes a flow that cannot start; the qualifier lives only on /refunds (apps/web/app/page.tsx:370).
12. [CLAIM] Privacy policy §2 references "an Apple identifier if you use Sign in with Apple" — SIWA is code-complete but inert (no entitlements file, unconfigured), so the policy documents a collection path no user can trigger yet (apps/web/app/privacy/page.tsx:60; CLAUDE.md gotchas).
13. [SEO] Legal/trust pages set only title/description/canonical, so Next's shallow metadata merge leaves the root `openGraph` (og:url=https://cerebrozen.in, homepage og:title) on /privacy, /terms, /support, etc. — every subpage shares as the homepage (apps/web/app/layout.tsx:32-39; apps/web/app/privacy/page.tsx:6-10).
14. [SEO] `keywords` meta is dead weight — ignored by every major engine since ~2009; ten generic terms add bytes and zero ranking (apps/web/app/layout.tsx:25-28).
15. [SEO] og:image declared 1200×628 rather than the recommended 1200×630; some scrapers letterbox off-spec ratios (apps/web/app/layout.tsx:38).
16. [SEO] `dynamic = "force-dynamic"` puts the whole marketing site on per-request SSR with no Cache-Control/CDN story — crawl budget and TTFB pay for the CSP nonce on every hit; a hash-based CSP or edge caching of the HTML would keep the policy without the cost (documented tradeoff, unmitigated) (apps/web/app/layout.tsx:54-58).
17. [SEO] Sitemap `lastModified` is a hand-bumped constant ("Bump this when the site's content actually changes") — a process that will silently drift stale the first time someone forgets, mis-signaling freshness for all 7 URLs (apps/web/app/sitemap.ts).
18. [PERF→SEO] The LCP hero image is a 177 KB JPEG at 970×1080 rendered into a ≤440 px-wide frame — >2× oversized, no srcset/AVIF/WebP, and `next/image` is unused across the site (plain `<img>`, `images` unconfigured) (apps/web/app/page.tsx:201-207; apps/web/public/brand/banner-hero.jpg; apps/web/next.config.mjs).
19. [PERF] Dead shipped assets: `public/screens/home.webp` (62 KB) is referenced nowhere, and `public/brand/banners/` is an empty committed directory (apps/web/public/screens/home.webp; apps/web/public/brand/banners).
20. [A11Y] Waitlist email input has no visible label — placeholder + `aria-label` only, failing the spirit of WCAG 3.3.2 (placeholder disappears on input; sighted-but-cognitively-loaded users lose the field's purpose) (apps/web/components/Waitlist.tsx:91-98).
21. [A11Y] Mobile nav is a native `<details>` with no dismissal wiring — choosing an in-page anchor (#features, #waitlist) leaves the panel open over the content the user just navigated to, and there is no outside-click/Escape close (apps/web/app/page.tsx:158-168).
22. [A11Y] FAQ uses `name="faq"` exclusive accordion — opening one answer force-closes another; a screen-reader or switch user reading answer A loses it the moment they open answer B, with no announcement (apps/web/app/page.tsx:381).
23. [SEQ] Pricing cards have no CTA — no "Start free" / "Upgrade" button or link on any of the three plans; the page's decision moment dead-ends and the visitor must rediscover the nav or footer to act (apps/web/app/page.tsx:356-369).
24. [SEQ] The page's closing band asks only for the waitlist — by the code's own comment the waitlist is "the *secondary* door", yet the final CTA section ("Be first to feel the calm") omits "Open the app"/signup entirely, ending the conversion path on the weaker ask (apps/web/app/page.tsx:16-17,390-412).
25. [SEQ] FAQ launch/platform answers name `app.cerebrozen.in` as plain text, not a link — the two answers most likely to convert a ready visitor make them retype the URL (apps/web/app/page.tsx:66,68).
26. [SEQ] Hero presents three CTAs of which two resolve to the secondary action — the App Store chip's default href is `#waitlist`, so "Open in browser" competes with two waitlist pointers; primary/secondary hierarchy is diluted at the top of the funnel (apps/web/components/AppStoreBadge.tsx:8; apps/web/app/page.tsx:184-188).
27. [BUG] JSON-LD `SoftwareApplication` declares a single Offer of ₹0 while the page sells ₹499/₹1,499 tiers — legal but lossy; an `AggregateOffer` (low 0, high 1499) would match the page and avoid rich-result price mismatch (apps/web/app/page.tsx:88-99 vs 46-52).
28. [BUG] Landing spaces copy for "You" promises "real support" and "Insights from your real check-ins" while `#waitlist` receipts carefully avoid superlatives — "real support" is un-inventoried phrasing the claims gate doesn't scan for and no mechanism row backs (apps/web/app/page.tsx:29).
29. [A11Y] The only favicon is a 32 px generated PNG; no larger icons or manifest exist for the marketing origin (only apple-touch-icon), so pinned tabs/bookmarks on high-DPI render a scaled blur (apps/web/app/icon.tsx; apps/web/public).
30. [SEQ] Stale-vs-shipped drift check (positive + residue): the page correctly leads with the browser app, but SPACES/bento copy still describes mobile-only capabilities (Face ID, offline tools, presence ring) without flagging surface — a "on iOS"/"in the apps" qualifier pattern exists nowhere in the copy system (apps/web/app/page.tsx:21-44).

## Admin dashboard (apps/admin)

31. [SEC] Broadcasting a nudge to every active user is a single unconfirmed click — "Queue for all active users" submits directly; meanwhile single-user disable requires a reason + confirm and content delete requires two clicks. The widest-blast action has the weakest guard (apps/admin/app/page.tsx:1408-1441; backend/app/api/routes/admin.py:494-519).
32. [SEC] Prompt "Activate" (old version) and "Revert to code default" are one-click with no confirmation — including for `safety_classifier`, where *saving* requires an acknowledgement checkbox plus a two-step confirm. Rolling the live risk prompt back to any historical version bypasses every guard the save path built (apps/admin/app/page.tsx:1237-1245,1274-1276,1354-1358).
33. [SEC] The disable-account reason is silently dropped: the panel requires and PATCHes a `reason` body, but `set_user_active` accepts only the `active` query param — FastAPI discards the body, so no record exists of who disabled which account or why (the frontend comment admits it) (apps/admin/app/page.tsx:606-626; backend/app/api/routes/admin.py:165-173).
34. [SEC] No persistent admin action log exists for content CRUD, media upload/clear/delete, prompt saves/activations, nudge broadcasts, or user enable/disable — `PromptTemplate` stores notes but not the author; only safety resolution records the acting admin. A malicious or mistaken operator is unattributable (backend/app/api/routes/admin.py throughout; backend/app/models/prompt.py).
35. [SEC] The safety-excerpt UI tells reviewers "the reveal is noted on the row" / "The server logged it", but the server only emits a `logger.info` line — nothing is persisted to the event row or any audit table, and log rotation erases the record. The UI overstates the trail the CLAIMS_MAP leans on ("a separate, logged, per-row GET") (apps/admin/app/page.tsx:1519-1522,1556-1558; backend/app/api/routes/admin.py:444-450).
36. [SEC] Waitlist CSV export has no formula escaping — cells beginning `=`, `+`, `-`, or `@` execute on open in Excel/Sheets, and the `source` field is attacker-controlled: public `POST /waitlist` accepts any string as `source` with no validation or length cap, which the admin then exports and renders (apps/admin/app/page.tsx:1668-1684; backend/app/api/routes/waitlist.py:16-18,30-37).
37. [SEC] Sign out never revokes the session server-side — `clearToken()` only clears memory/localStorage; `POST /auth/logout` exists and is never called, so a previously exfiltrated refresh token remains valid after the admin "signs out" (apps/admin/lib/api.ts:19-22; backend/app/api/routes/auth.py:285).
38. [SEC] Admin login performs no role check at sign-in — it uses the shared `/auth/login`, so any valid *user* credential "signs in" to the shell, then every call 403s, the refresh succeeds, the retry 403s again and the client clears the session with the misleading "Your session ended". The error copy also asserts "don't match an admin account" for credentials that may be a perfectly valid user account (apps/admin/app/page.tsx:141-168; apps/admin/lib/api.ts:136-139).
39. [SEC] No MFA for admin accounts — a single password guards a surface exposing every user email, private crisis excerpts, prompt control over risk detection, and all-user push messaging (backend/app/api/routes/auth.py; no TOTP/WebAuthn anywhere).
40. [SEC] The refresh token persists in localStorage — the access token was moved to memory *because* XSS can lift storage, but the longer-lived, single-use-rotating credential still sits in the exact place that reasoning condemns; an httpOnly cookie would close it (apps/admin/lib/api.ts:4-11).
41. [SEC] Content `image_url` is any raw string — no scheme/URL validation server-side; whatever an operator pastes is persisted and served to every client app for rendering (admin CSP allows all https images specifically for this) (backend/app/api/routes/admin.py:192-201; apps/admin/middleware.ts:42; apps/admin/app/page.tsx:1038).
42. [ADMIN] `GET /admin/safety` is unbounded — no limit, offset, or pagination server- or client-side; the triage queue fetches every event ever recorded on each tab open, and the resolved view grows forever (backend/app/api/routes/admin.py:417-426; apps/admin/app/page.tsx:1478-1481).
43. [ADMIN] Content library: unbounded list, no pagination, no search, no kind/tier/status filter — the flat table is the only navigation once the catalogue grows past a screen (backend/app/api/routes/admin.py:177-180; apps/admin/app/page.tsx:1101-1155).
44. [ADMIN] Waitlist: unbounded list with no pagination or search; the CSV silently exports only what loaded (currently everything, which is its own problem at scale) (backend/app/api/routes/waitlist.py:40-43; apps/admin/app/page.tsx:1673-1684).
45. [ADMIN] Nudges tab is silently truncated — the UI passes no `limit`, the backend defaults to 100 (cap 500), and there is no "load more", search, or status/kind filter; older sends simply vanish with no indication the list is partial (apps/admin/app/page.tsx:1375; backend/app/api/routes/admin.py:522-531).
46. [ADMIN] Users "Load more" grows `limit` and refetches the entire result set from row zero — the backend supports `offset` but the client never uses it; each click re-transfers everything already shown (apps/admin/app/page.tsx:519-523,584-587; backend/app/api/routes/admin.py:83-97).
47. [ADMIN] No loading state exists anywhere — `useData` starts `data=null`, so every tab renders an empty table while in flight and the headers assert wrong facts during load: "0 shown", "0 items", "0 signups". Loading, empty, and slow-network states are visually identical until resolve (apps/admin/app/page.tsx:208-226,538,989,1691).
48. [ADMIN] Analytics onboarding-funnel errors are swallowed — the second `useData` call destructures only `data`, so a failed `/admin/metrics/funnel` silently removes the panel with no message or retry (the overview fetch gets full error handling one line up) (apps/admin/app/page.tsx:377).
49. [BUG] Multiple mutations have no catch: Content `save` (create/edit form) is try/finally only, Content `patch` (publish/premium toggles), Users `setActive` (enable), and Prompts `activate` all reject unhandled — the operator gets zero feedback and the form/row stays in its pre-action state with no explanation (apps/admin/app/page.tsx:933-955,953-956,530-533,1237-1240).
50. [BUG] Media `clearAsset` failure is silent — `finally` resets the busy flag but there is no catch and no message; contrast `onPick` one function up which reports errors (apps/admin/app/page.tsx:790-805).
51. [ADMIN] Media "Clear" orphans files on disk — it PATCHes `url:""` but `media.delete_asset` runs only on row DELETE, so every cleared upload leaves its bytes in the assets dir forever (apps/admin/app/page.tsx:796-799; backend/app/api/routes/admin.py:352-364 vs 367-375).
52. [ADMIN] Safety queue timestamps show date only — `fmtDate` (no time) renders `created_at`, so crisis triage cannot distinguish a flag from five minutes ago from one from twenty hours ago; `fmtWhen` (with time) exists but is used only for resolution stamps (apps/admin/app/page.tsx:1576 vs 1466-1474).
53. [ADMIN] A crisis flag cannot reach its user — `SafetyEventOut` carries `user_id`, but the Safety tab never displays it or links to the account, so an operator cannot check the user's trusted contact, tier, region, or open-event history without manually hunting in the Users tab (backend/app/schemas/content_data.py:221; apps/admin/app/page.tsx:1536-1612).
54. [ADMIN] "Closed by {resolved_by}" renders a raw admin UUID — the API returns the resolver's id, not name/email, and the UI prints it verbatim; the one attribution the system does record is unreadable to the humans it's for (apps/admin/app/page.tsx:1581; backend/app/schemas/content_data.py:227).
55. [ADMIN] Tabs are pure component state — no URL routing at all: refresh always resets to Overview, no tab can be bookmarked, deep-linked, or opened in a new window, and the browser back button exits the dashboard (apps/admin/app/page.tsx:33,88).
56. [ADMIN] Two operator endpoints have no UI: `/admin/agent-actions` (per-tool accept/decline rates — the Oracle tab's missing half) and `/admin/digest/run` (the manual weekly-digest pass that cron-only deployments *require*) are reachable only by curl (backend/app/api/routes/admin.py:557-590; apps/admin/app/page.tsx TABS).
57. [ADMIN] Oracle "Awaiting a decision" is display-only — stuck confirmations are listed with age but no operator action (expire, cancel, inspect thread), so the tab can diagnose but never resolve the exact condition it warns about (MemorySaver restarts) (apps/admin/app/page.tsx:1784-1801).
58. [ADMIN] Related nudge tasks are split across tabs — "Dispatch due nudges" lives on Overview while authoring and the queue live on Nudges; and dispatch reports only `{sent}` although the Nudges tab promises "honest sent/skipped/failed outcomes" the response never carries (apps/admin/app/page.tsx:296-307,1404-1407; backend/app/api/routes/admin.py:551-554).
59. [BUG] No `oracle` key exists in the Icon record — the Oracle tab silently renders the Overview glyph through the fallback, producing a duplicate sidebar icon; the fallback added so "a missing icon must never take down the dashboard" is now masking a real omission (apps/admin/components/icons.tsx:29-47; apps/admin/app/page.tsx:82).
60. [A11Y] Admin defines no `:focus-visible` style anywhere, and the login inputs set `outline: none` — keyboard focus is fully invisible on the credential form and only browser-default elsewhere (web's globals.css has a documented site-wide ring; admin's has none) (apps/admin/app/globals.css:109 vs apps/web/app/globals.css:78-82).
61. [A11Y] Sidebar tabs are bare `<button>`s with `aria-current="page"` (a link semantic on a non-link) and no tablist/tab/tabpanel relationship; tables use empty `<th>` for action columns and no `scope` attributes, so screen readers announce unlabeled columns (apps/admin/app/page.tsx:84-92,552-556,1104).
62. [A11Y] Row-action and `.btn-sm` controls are ~26-30 px tall — well under the 44 px target the web app's own CSS comments treat as the floor; dense danger buttons ("Delete") sit flush beside safe ones in the same cluster (apps/admin/app/globals.css:87-91,131; apps/admin/app/page.tsx:1124-1147).
63. [A11Y] Users search input has no label (placeholder + decorative icon only), and the "N shown" result count is not a live region — screen-reader users typing a filter get no announcement that results changed (apps/admin/app/page.tsx:538-547).
64. [BUG] `fmtDate`/`fmtWhen` try/catch is dead code — `new Date("garbage")` never throws, it returns Invalid Date, so malformed input renders the string "Invalid Date" instead of the intended raw-value fallback (apps/admin/app/page.tsx:22-28,1466-1474).
65. [BUG] Waitlist rows use the array index as the React key — safe only while the list never reorders; a future search/sort on this table would recycle rows incorrectly (apps/admin/app/page.tsx:1702).
66. [BUG] `upload()` doesn't wrap fetch for network failure — an offline media upload throws a raw `TypeError: Failed to fetch` which the Media tab surfaces verbatim via `setMsg(String(e.message))`, unlike every JSON call which maps to the friendly `ApiError("offline")` copy (apps/admin/lib/api.ts:167-187; apps/admin/app/page.tsx:775-788).

## XSS note (checked, not a finding)

User content shown to admins (safety excerpts, nudge titles, waitlist emails/sources, journal-derived
reasons) is rendered exclusively through React text nodes — no `dangerouslySetInnerHTML` outside the
landing's JSON-LD — so stored-XSS via user content is not currently reachable. The CSV export (#36)
is the one path where user-controlled strings escape React's escaping.
